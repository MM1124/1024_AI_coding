# 1024_AI_coding · 需求拆解与排期闭环 Demo

面向「部门目标落地」场景的需求驱动型工作台演示：从**需求导入**切入，经人工确认的**功能点**作为唯一事实源（SSOT），向下智能生成**分析 / 开发 / 测试 / 验收**四阶段的计划与排期，最终由**验收评估**闭环回目标达成度。

> 对应赛题三问：**拆得科学**（SMART 逐级拆解）· **管得住**（进度 / 变更 / 前置预警）· **验得回来**（对照标准评估，可追溯可对比）。

---

## 快速开始

零依赖、零构建，**双击 `app/index.html` 即可运行**。

如需本地 HTTP 预览：

```bash
cd app
python3 -m http.server 8899
# 浏览器打开 http://127.0.0.1:8899/index.html
```

首次打开会自动写入 `localStorage` 演示数据；侧边栏「重置演示数据」可恢复初始状态。

## 目录结构

```
app/
  index.html     入口页（侧边导航 / 身份切换 / 演示时点 / 弹窗与提示容器）
  styles.css     全站样式（布局 / 卡片 / 表格 / 泳道 / 响应式）
  data.js        MOCK 数据 + 预置 AI 解析结果（功能点、计划、变更单、验收记录等）
  engine.js      确定性引擎（纯函数，无 DOM 依赖）
  app.js         视图与交互层（6 视图 + 事件委托 + 权限拦截 + hash 深链）
  verify.js      引擎规则断言（Node 直接可跑）
  ui-smoke.js    DOM 桩全链路冒烟（Node 直接可跑）
docs/
  开发日志-*.md   迭代记录（每轮优化的改动与踩坑）
```

### 分层约定

| 层 | 文件 | 职责 |
|---|---|---|
| 数据 | `data.js` | 只放事实，不含逻辑 |
| 引擎 | `engine.js` | 纯函数计算：排期推荐、门禁校验、达成度、偏差、预警、按阶段分桶、看板统计 |
| 视图 | `app.js` | 渲染 + 事件委托；不含业务算法 |
| 校验 | `verify.js` / `ui-smoke.js` | 引擎规则 + 真实点击全链路 |

新增能力一律走 **数据 → 引擎 → 视图 → 交互 → 验证** 的顺序，先补断言再改实现。

## 核心机制

### 1. 排期引擎（单一日历，三阶段复用）

`E.recommendSchedule` 采用统一算法：按人取「已有占用日历」，从最早开始日起逐日填充工时，**单日上限 7.6 ~ 8.5 小时**，超出自动顺延到下一个工作日。

- 分析 / 开发 / 测试三个阶段共用同一引擎，口径一致
- 推荐时排除自身占用（`excludePlanId` / `excludeTestId`），避免自己把自己挤走
- 手动改期按工作日平分，超限给出提示而非报错

### 2. 功能点 = SSOT，锁定后不可解锁

产品经理人工确认后需求即**锁定**，功能点成为基准，**不提供解锁入口**。锁定后的任何增删改（含新增功能点）都必须走**变更单**：填写变更前后、原因、影响 → 管理者审批 → 通过后落库并生成新版本（v1.0 → v1.1）。

### 3. 阶段门禁与分角色流转

四阶段 `分析 → 开发 → 测试 → 验收 → 已验收`，每次流转前 `E.stageGate` 校验前一阶段结果是否收敛（功能点锁定、任务全部完成、无待审变更单等），未通过则按钮禁用并提示待完成项。

每个阶段有明确归属（`STAGE_OWNER`：分析/验收 → PM，开发 → DEV，测试 → QA），只有本阶段 owner 能看到并提交该段流转，越权在动作层二次拦截。

### 4. 任务与测试记录

开发任务按功能点引入，引入时若存在关联系统会提示**是否为关联系统自动创建任务**；每生成一条开发任务，**默认派生一条测试记录**（1:1）。测试排期与开发排期算法同构——按当前负载择优挑人、逐人维护游标、最早开始日继承开发完成日（上下游关系），**不预设固定单人**。

### 5. 预警规则

| 规则 | 触发条件 |
|---|---|
| 到期提醒 | 工作量 > 10h → 到期前 **2 天**；≤ 10h → 到期前 **1 天** |
| 插队影响 | 需求插队 / 被插队，在插队看板评估并顺延后续任务 |
| 关联系统倒挂 | 关联系统排期完成日晚于主系统 → 提示当前操作人 |

侧边栏「演示时点」可改日期，直接验证提醒边界。

### 6. 验收评估闭环

功能点逐条验收（对照 AC + 实测 + 证据 + 结论 + 得分）→ 需求加权达成度（P0=3 / P1=2 / P2=1，未验收计 0）与评级 → 计划 vs 实际偏差（**计划生效时冻结 `baselineStart/End`**）→ 部门目标达成度（挂靠需求、目标值对比）→ 组织验收结论 → 员工复盘。结果可追溯、可对比，支持导出 CSV / JSON。

## 角色与视图

| 角色 | 默认落地页 | 主要能力 |
|---|---|---|
| PM 产品经理 | 需求工作台 | 需求导入、功能点确认与锁定、分析排期、阶段提交 |
| DEV 开发负责人 | 排期中心 | 开发排期、关联系统建单、任务状态维护 |
| QA 测试工程师 | 执行跟踪 | 测试排期（择优挑人）、测试记录状态维护 |
| MGR 管理者 | 验收评估 | 变更审批、里程碑、组织验收结论 |

可见页签由 `ROLE_VIEWS` 控制，越权访问自动回落到本角色首页。**数据看板为全角色可见**（只读统计，不涉及越权动作）。侧边栏「角色能力矩阵」可查看完整权限对照。支持 hash 深链直达（如 `index.html#dash`、`#track`），便于演示与截图。

## 视图一览

1. **需求工作台** — 需求队列按**阶段分组**展示：顶部阶段流水线概览（五阶段全部露出、空阶段淡显），下方按「分析 / 开发 / 测试 / 验收 / 已验收」分段陈列卡片；点卡片进单需求详情（导入 / 功能点 / 阶段流转）
2. **排期中心** — 分析 / 开发 / 测试三张独立计划卡 + 计划外工作；自动排期、推荐周期采用、改期
3. **计划看板** — 按人泳道的时间轴（分析 / 开发 / 测试三色），窗口可调
4. **执行跟踪** — 任务与测试状态逐笔维护、进度统计、变更审批入口
5. **验收评估** — 功能点验收、达成度、偏差、目标闭环、复盘与导出
6. **数据看板** — 月度需求数量变化（柱 + 趋势折线）、部门维度分布、月度分析/开发/测试工作量（支持按阶段 / 业务部门 / 关联系统 / 实施人四种维度切换）；全部用零依赖纯 SVG + CSS 绘制

## 设计取舍

- **零依赖零构建**：现场演示不能有网络 / 依赖安装风险，纯静态单页双击即跑
- **确定性内核 + 演出层**：AI 拆解以预置数据 + 流式打字动画呈现，替换为真实模型调用只需替换 `parsePresets` 一段
- **权限双层拦截**：按钮 `disabled` 只是可见层，动作层 `deny` 才是真正兜底
- **品牌与视觉**：侧边栏承载品牌区，slogan「服务小微，服务大众」置于品牌标题下方作为价值主张；导航项采用编号 + 标题 + 副标题的三段式层级，选中态用蓝色胶囊 + 左侧指示条强化；按钮分 `primary / 次级 / ghost / danger` 四级，表单控件统一为矩形 + 右侧箭头并带聚焦蓝环，与按钮形成明确区分
